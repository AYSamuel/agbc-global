# W2.3 · Compose slice: execution plan

Build blueprint for the first work item where the app WRITES user content. Behavioral
truth is `09-FEATURE-Family.md`; Art. 9 truth is `20-PRIVACY-COMPLIANCE.md`; the write
path is `02-DATA-MODEL.md`. This doc adds sequencing, the resolved decisions, and the
implementation nuances found while planning (2026-07-26). Delete once W2.3 lands. Read
`09` + `20` + `02` first-hand in the build session, and read the compose frames in
`design/mockups/entry-flow.html` first-hand before writing any screen code.

## What is already done (do not rebuild)

- **The entire write path is enforced** (W1.5 migration): INSERT policies
  `members share a testimony` / `members share a request`
  (`author_id = auth.uid() and status = 'pending' and caller_is_onboarded()`), insert
  guards forcing authorship, branch, pending status and zeroed counters, and
  `assert_content_quota()` (5 posts per author per rolling 24h). W2.3 adds no INSERT
  policy: the composer writes into a door that was already locked correctly.
- **The gate is already wired.** `GateAction` in `apps/mobile/src/state/gate.ts` carries
  `{ kind: 'compose', target: 'testimony' | 'prayer' }`, the FAB and both empty-state
  CTAs on FAMILY already open it, and `features/auth/replay.ts` reserves `compose`.
- `testimony_categories` seeded with 8 rows and readable by guests; `family.json`
  already carries the matching `categories.*` labels.
- Form pattern from W2.1: react-hook-form + shared zod schema, i18n error copy (never
  zod's message), `TextField`, `AppHeader`, `useToast`.

## Resolved decisions (2026-07-26)

1. **One branch, one PR, commit per slice** (revised 2026-07-27): BE, then the composers,
   then the photo. The photo still needs native modules the current dev clients do not
   carry, so it lands only after the batched EAS dev build; slices 1 and 2 add no native
   module at all and run on the existing dev clients today.
2. **`consent_version` becomes a real reference** (lookup table + FK + activeness check)
   rather than free text. Art. 9 evidence a client can invent is not evidence.
3. **Body caps in the database**: testimony 2000, prayer 1000. `09` and `02` synced.
4. **Signed URLs come from storage RLS, not an edge function** (`02` amended). The
   policy gives the identical guarantee with no extra service on the read path.

## Slice 1: Compose BE (`feat/w2-3-compose-be`)

- `consent_versions` lookup + FK from both content tables +
  `assert_consent_version_active()` in the insert guards. The first row
  (`content-share-v1`) ships IN THE MIGRATION, not in `seeds/00-common.sql`: `db push`
  carries migrations to dev and prod but never the seed files, and without an active
  version the whole compose path is dead. A backfill adopts any pre-existing version as
  inactive so the FK cannot fail a deploy.
- Body-length CHECKs replacing the not-blank constraints; mirrored in
  `packages/shared/src/contracts/family.ts`.
- `testimonies.image_url` renamed to `image_path` (private bucket holds paths, not
  URLs), the feed view rebuilt, both testimony guards re-emitted.
- `assert_photo_path_owned()`: the photo reference must sit in the author's own folder,
  because the read policy hangs on "is an approved testimony pointing at this object".
- `testimony-photos` bucket (private, 5 MiB, jpeg/png) + `storage.objects` policies:
  write inside your own folder, read your own object OR an approved testimony's OR one
  you moderate.
- pgTAP `013-compose-consent-photos.sql` (25 tests): invented and retired consent
  versions refused, the FK refused even to a privileged writer, body ceilings at the
  boundary, a stranger's photo object unclaimable, and the read boundary walked through
  pending → approved for guest, outsider, author and leader.
- Seeds and the 008/009/010 fixtures moved onto the real consent version; types
  regenerated; `02` and `09` synced in the same PR.

## Slice 2: Composers, consent, pending (`feat/w2-3-compose-screens`)

Mockup-first: frames at `entry-flow.html` L1141 (TESTIMONY-COMPOSE), L1157 (CONSENT),
L1176 (POST-PENDING), L1604 (PRAYER-COMPOSE). Read them in the build session and diff
element-by-element; a behavioral walkthrough is not visual verification.

- **Routes** `app/testimony/compose.tsx` and `app/prayer/compose.tsx`, each a three-step
  state machine (compose → consent → sent) in one route, mirroring `AuthFlow.tsx`. The
  frames confirm the shape: compose is the `.chead`/`.screen` layout, CONSENT reuses the
  AUTH `.authwrap` layout, POST-PENDING reuses AUTH-4's `.success` layout.
- **New primitives**: `TextArea` (multiline, 140px min height, counter near the cap),
  `Checkbox` (extract the hand-rolled one from `ProfileStep.tsx` so consent, anonymity
  and the 16+ row share it), and `leading: 'back' | 'close'` on `AppHeader` for the X.
- **Consent step** wording in `family.json` under `consent.*` in all four languages,
  pinned to `CONSENT_VERSION` by a hash test so copy cannot drift without a version bump.
  Includes the `20` §Photos reminder once slice 3 lands the picker.
- **Draft persistence** (`09` §3): AsyncStorage per composer, debounced, restored with a
  "Draft restored" toast, cleared on success. Consent is NEVER persisted; the step
  re-runs after a restore.
- **Submit**: the app's first `useMutation`. Insert
  `{ body, language, category_id, is_anonymous, consent_version }` and let the triggers
  force the rest; invalidate `['family']`. Error mapping: `check_violation` + "daily
  sharing limit" → grace-framed cap copy; network → keep the draft, offer retry (queued
  writes are W2.4); otherwise generic retry.
- **Gate replay**: `replayGateAction` handles `compose` by pushing the route.
- Tests: RNTL per composer (validation, consent gating submit, success → POST-PENDING,
  cap copy, draft restore) plus unit tests for the draft store and the replay.
- Deviations to flag: "Add a photo" hidden until slice 3; POST-PENDING's "View my posts"
  link omitted until MY-POSTS exists (W2.6, `04` forbids dead ends); the prefilled linked
  composer (frame L1325) waits for W2.5, which builds its only entry point.

## Slice 3: Photo (`feat/w2-3-compose-photo`), after the EAS rebuild

- `expo-image-picker` + `expo-image-manipulator` behind guarded requires (the
  `features/give/CopyRow.tsx` pattern) so older dev clients degrade instead of crashing.
- Pick → re-encode to JPEG (~1600px max edge, quality ~0.8; the re-encode is what strips
  EXIF/GPS) → upload to `testimony-photos/<uid>/<uuid>.jpg` → store the path.
- `photo-guard` edge function (index/core/core_test split): service-role, reads the
  object's leading bytes, deletes the object and nulls the row on a magic-byte mismatch.
  The bucket's mime allowlist and size cap are the layers underneath it (`02`,
  `~/.claude/standards/security.md` §File uploads).
- `useSignedPhotoUrl` (short TTL, cached in TanStack Query) used by `TestimonyCard` and
  TESTIMONY-DETAIL.
