## 1. Edge-to-edge deprecated APIs: NOT OURS, and nothing to build

Play lists the exact entry points. Every one is library code:

```
com.facebook.react.modules.statusbar.StatusBarModule.getTypedExportedConstants
com.facebook.react.views.view.WindowUtilKt.statusBarHide
com.facebook.react.views.view.WindowUtilKt.statusBarShow
com.google.android.material.bottomsheet.BottomSheetDialog.onCreate
com.google.android.material.internal.EdgeToEdgeUtils.applyEdgeToEdge
com.google.android.material.sidesheet.SheetDialog.onCreate
```

for `Window.getStatusBarColor`, `Window.setStatusBarColor`,
`Window.setNavigationBarColor` and the two `LAYOUT_IN_DISPLAY_CUTOUT_MODE` constants,
all deprecated in Android 15.

**There is no line of ours that calls any of them.** React Native's own status-bar
module and Google's own Material components do, and it clears when those upgrade. No
deadline is attached. This item exists in the plan only so the next person who opens
that console panel does not spend an afternoon looking for our call site.

## 2. Orientation: a real bug, and `05` has always said so

Play found, in the manifest of build 22:

```xml
<activity android:name="com.oami.agbcapp.MainActivity"
          android:screenOrientation="PORTRAIT" />
```

which comes from `orientation: 'portrait'` in `app.config.js`. Two places in this
repo's own spec contradict it:

- `05` §Tablet: "player and reader support landscape on all devices", and "Android
  16+ ignores orientation/resizability locks on large screens, so tablet rendering is
  not optional".
- `lib/layout.ts`: "the only screen this app lets a phone rotate to is the sermon
  player, where turning the device means 'make the video bigger'". That sentence
  describes behaviour the manifest forbids.

**What the bug actually costs.** W4.7 built real tablet layouts: the nav rail, Watch's
two-pane, Home's dashboard grid, four content measures. **A tablet on Android 15 or
below is held in portrait by that attribute and can never reach any of them.** On
Android 16 the platform ignores the lock, which is the only reason the tablet work was
testable at all. So those layouts currently exist for one Android version.

### What gets built

**The lock moves from the manifest to the app**, where it can be conditional.

- `app.config.js` becomes `orientation: 'default'`. The prebuilt manifest then says
  `android:screenOrientation="unspecified"`, which is Android's no-restriction default.
  **The attribute is not removed**, because Expo offers no way to omit it, so what Play
  gets is a value that restricts nothing rather than an absent key.
- The app locks itself to portrait ON A PHONE, at the root, using
  `expo-screen-orientation`, which is **already a dependency** and already linked
  (`useLandscapeAllowed` has used it since W3.1). No new native module, no new build
  fence.
- A tablet is never locked, so it rotates on every Android version rather than only on
  16.
- The player keeps doing exactly what it does now: unlock on the way in, put the lock
  back on the way out, and the "put it back" becomes a no-op on a tablet.

`isTablet` is smallest-width (`lib/layout.ts`, Android's own `sw600dp`), so it is
stable across rotation and cannot flip mid-session.

### What this deliberately does NOT do

**It does not free rotation on phones.** `05` decided against that, with a reason worth
keeping: a phone in landscape is over 1000dp wide but is still a phone, and every
screen would then need verifying at roughly 400dp of height, with a keyboard, at large
font scales. That is the worst cell in the responsiveness matrix and no member is
asking for it.

### The honest costs, both worth stating before the PR

1. **A launch window appears that the manifest did not have.** A phone launched while
   held sideways can render one frame in landscape before the lock lands. The manifest
   attribute was applied by the system before the activity existed. Small, visible
   once, and the price of the lock being conditional at all.
2. **The safety property inverts.** Today, if `expo-screen-orientation` is missing the
   app still cannot rotate, because the manifest holds it; the guarded require fails
   safe. Afterwards, a missing module means free rotation into screens never verified
   in landscape. In production this cannot happen (the module is linked in every EAS
   build), but an old dev client would rotate freely.

**And the thing not to pretend:** moving a restriction out of the manifest is also what
makes Play's static check stop reporting it. That is not the reason for the change and
must not become the reason. The reason is the Android 15 tablet.

## 3. Obfuscation: R8, and it cannot be verified by any test

**"App optimization is below our threshold", obfuscation at 1%, fix by Feb 2027.** Its
other face is the warning on every upload: "There is no deobfuscation file associated
with this App Bundle." Both clear together.

Built with `expo-build-properties` (a config plugin, not runtime native code), setting
`enableMinifyInReleaseBuilds` for release builds. **Minify only.** The flagged category
is obfuscation, which minification alone answers; `enableShrinkResourcesInReleaseBuilds`
would strip assets it cannot see referenced, which is a second and unrelated way to
break a release for no gain against the thing Play asked for.

The "no deobfuscation file" warning needs no upload step: with minification on, the
Android Gradle plugin writes the mapping into the bundle itself
(`BUNDLE-METADATA/com.android.tools.build.obfuscation/proguard.map`) and Play reads it
from there.

**The risk is specific and it is why this slice ships unverified until a real install.**
R8 removes classes it cannot see being used, and React Native, Hermes and every Expo
module find things by reflection. A stripped class does not fail a build, a unit test,
a typecheck or a lint: it throws at runtime, on the screen that needed it. Every layer
in this repo would stay green.

**So the acceptance test is an installed release artifact**, not a suite: whichever
bundle first carries this, installed from Play's internal testing track, then walked
through the app. **That release must not go to production before the walk.** This is the same shape as the
placeholder icon at W4.8: green everywhere, wrong on the phone, because the one surface
no test looks at is the built artifact itself.
