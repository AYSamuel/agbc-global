## 1. Decisions, with the reasons

- **Both stores ship 1.0.2, built from one commit on `main`** (Ayo, 2026-09-14, picked over two
  alternatives). Android 1.0.1 (23) was built from tag `v1.0.1`, and `main` has since gained
  W4.11 (tablet orientation, R8), W4.15 (share as a picture), W4.16's app (the rhythm calendar,
  whose database is already live) and #264 (Expo SDK 57 alignment, React Native 0.86.3). An iOS
  build from the tag would have carried the portrait lock W4.11 removed, onto iPads, and any fix
  the first iOS build needed would have had to land twice. An iOS "1.0.1" from `main` would have
  meant two different apps under one version number, and the release table would have stopped
  being true. So Android gets a release it was already waiting for, and both stores carry the
  same code under the same number.
- **iOS ships WITHOUT verification on an Apple device** (Ayo, 2026-09-14). There is no iPhone
  in the project. What this accepts, said once so nobody rediscovers it: Apple's reviewer is the
  first person to open the iOS app; a crash there costs a rejection, one of the month's 15 iOS
  builds and a few days, not members; and nothing iOS-only has been seen working (background
  audio and the lock screen, push through APNs, universal links, the share sheet with a PNG,
  the iPad layouts, the update notice). `18`'s iOS E2E line stays open rather than being ticked.
- **iPad is supported, and was never a choice.** Grace Portal 1.0.0 (18) supports iPad (the live
  listing names 80 iPad models and carries iPad screenshots), and an update may not drop a device
  family the version before it supported. Expo defaults `ios.supportsTablet` to false, so the
  first upload would have failed without it. It costs 13" iPad screenshots.
- **The minimum iOS version rises from 15.6 to 16.4.** Grace Portal supported 15.6; SDK 57's
  Expo modules declare 16.4 (`ExpoModulesCore.podspec`). An iPhone below 16.4 keeps Grace Portal,
  which the App Store does on its own. No decision to make, but it belongs in the record.
- **W4.10's iOS update notice is switched on** with `ios.infoPlist.AppStoreID`. The reasoning,
  including why it cannot fire before AGBC Global is on the store, is on the key in
  `app.config.js`.
- **The store links in the app and on the website wait until AGBC Global is LIVE on iOS.**
  `APP_STORE_URL` in `apps/mobile/src/lib/links.ts` and `appStoreUrl` in `Desktop/agbc`
  `src/lib/site.ts`. Filled today they would send an iPhone to Grace Portal, whose sign-in is
  retired. The association file does not wait (§3, slice 5).

## 3. The slices, in order

Every commit, push, tag, submission and secret change waits for Ayo's explicit go, one at a time.

- [ ] **Slice 1 · Config and corrections (one PR).** `version` 1.0.2 (and `package.json`);
      `ios.supportsTablet`, `ios.config.usesNonExemptEncryption`, `ios.infoPlist.AppStoreID`,
      each with a test in `__tests__/app-config.test.ts` that was mutation-checked; the AASA
      comment corrected (the Team ID is on the Membership page, not only in App Store Connect).
      Docs: `19` and `credentials.md` (the last iOS build was 18; the Apple row), `18` (the
      no-device decision on the Apple and iOS E2E lines), `store-submission.md` §3b, `25`'s board
      entry, and this file. Verified: typecheck, lint, `i18n:check`, `store:check`, the mobile
      suite, and `expo config --type introspect` showing the Info.plist and entitlements.
- [ ] **Slice 2 · Signing (Ayo, in PowerShell, one step at a time).** `eas credentials -p ios`
      signs in to Apple (two-factor, so interactive). EAS cannot reuse the existing distribution
      certificates without their private keys, so it makes its own; that is safe on iOS, where
      the identity that must never change is the bundle id and the team, not the certificate.
      Same session: the **APNs key** (the team has none) and an **App Store Connect API key** for
      `eas submit`. Then `eas build:version:set -p ios` to 23, so the production profile's
      auto-increment makes iOS build 24 alongside Android's 24. Check each command against
      Expo's current docs at the time, never from this file.
- [ ] **Slice 3 · Tag and build.** Tag `v1.0.2` on the merged commit (`releases.md` step 2),
      then `eas build --platform android --profile production` and `eas build --platform ios
      --profile production` from it. Record build ids, commit and fingerprint.
- [ ] **Slice 4 · Android 1.0.2 walked by hand, then uploaded.** Convert the AAB and install it
      on the S22 (the route W4.8 used for build 21). The walk is owed by four earlier items and
      no suite can stand in for any of it: W4.11's **R8** (every screen that loads a native
      module: Watch video and audio, the player and lock screen, sign-in, testimony photo pick,
      share as a picture, notifications, the map), `18`'s **tray icon** on a real push, W4.16's
      **rhythm** ring and Next card, and W4.15's **share cards**. Upload by hand, release notes

- [ ] **Slice 6 · App Store copy and screenshots (one PR).** **Most of the copy already exists**:
