## What the pre-build survey found

The item's own description implies a translation pass. Measured, that is not where the work
is. Five findings, and the first reshapes the whole item.

### 1. The parity check everyone would write is wrong in BOTH directions

A naive "does every EN key exist in DE/NL/FR" comparison reports:

- **16 keys missing** across DE (6), NL (6) and FR (4). All false. They are
  `_ordinal_one/two/few` forms. English ordinals have four categories (1st, 2nd, 3rd, 4th);
  German and Dutch ordinals have exactly one (`other`), French has two. Those keys **must
  not exist** in those locales.
- **3 keys "extra"** in FR. All real and required: French has a `many` cardinal category that
  English, German and Dutch do not.

Run the same comparison against the categories each language actually declares
(`Intl.PluralRules(lang).resolvedOptions().pluralCategories`, cardinal and ordinal) and the
picture inverts:

| Locale | Missing | Unexpected |
|---|---|---|
| DE | 0 | 0 |
| NL | 0 | 0 |
| FR | **26** | 0 |

DE and NL are **complete**. FR is missing 26 `_many` forms, of which exactly 3 were ever
written (`common:weeks_many`, `common:more.rhythmWeeks_many`, `watch:resultsCount_many`, all
in the original wiring commit `82690c0`). The other 26 have been absent since.

**The naive instrument reported 16 problems that were not there and hid 26 that were.** This
is the W4.7 lesson from the other side: an instrument that cannot fail is not evidence, and
an instrument that fails on the wrong thing is worse, because it trains you to ignore it.

French `many` fires at 1,000,000 and above, so **none of the 26 is reachable in this app**
(glory counts, characters left, minutes ago). They are filled anyway, because the done
criterion is "no missing-key warnings in any locale" and a check with 26 known-benign
failures is a check that gets muted.

### 2. A missing key renders as the key, in silence

W4.7 shipped `t('watch:title')` to a device, where i18next drew the literal word "title".
No test noticed, because nothing checks that a call site's key exists. Parity between locales
would not have caught it either: the key was missing from **all four**.

So the check has two halves, and only the second is what `22` §4 asks for:

1. every `t('ns:key')` literal in the app resolves to a real EN key;
2. every EN key has the forms each locale's CLDR categories require.

### 3. Only one string is genuinely untranslated

44 distinct keys hold a value byte-identical to English in at least one locale. Nearly all are
correct: proper nouns (`AGBC Global`, `Grace Academy`, `PayPal`), interpolation-only templates
(`{{greeting}}, {{name}}`, `{{value}}x`), and true cognates (`Format` in DE/FR, `Contact` in
NL/FR, `Notities`/`Notes`, `Pause`, `Audio`, `Video`, `Privacy` in NL).

The exception is **`common:tagline`**, "One family · many nations · one amazing grace",
identical in all three and known to be so: `i18n.test.ts` says "tagline is deliberately EN-only
until the W4.6 translation pass".

The triage is recorded rather than repeated, so the next reviewer inherits the reasoning
instead of re-deriving it.

### 4. The legal link does not follow the reader

`links.ts` hardcodes `https://agbcglobal.com/privacy` and `/terms`, and carries a TODO for this
item to confirm the paths. Confirmed live: both return 200, and so do the locale-prefixed
forms the website actually serves (`/de/privacy`, `/fr/privacy`, `/nl/terms`, all 200). The
website is URL-prefixed i18n with English unprefixed.

So a member reading the app in German taps Privacy and gets the **English** policy, while a
German one exists. The website already holds all four languages of privacy, terms and
Impressum in `src/i18n/legal.ts`, typed `Record<Lang, LegalDocs>` so a missing locale is a
build error there.

### 5. The PRIVACY screen does not exist, and Settings quietly replaced it

`04` line 137 lists `Privacy (PRIVACY)` as a screen. The frame draws it: a plain-language
summary in four sections, a "Contact us about my data" button, a link row out to the full
policy, and a delete-account line. What the app has is a `MenuRow` that calls
`WebBrowser.openBrowserAsync(PRIVACY_URL)`.

## Slices

### S1 · The missing-key check that can fail

- A CLDR-aware parity test: for each locale, derive the required key set from EN using that
  language's own cardinal and ordinal categories; assert none missing and none unexpected.
- A call-site test: scan the app for `t('...')` literals and assert each resolves in EN.
- Fill FR's 26 `_many` forms.
- **Mutation-check both**, in the direction that matters: delete a real FR `_many` and watch
  only the parity test go red; reintroduce `t('watch:title')` and watch only the call-site
  test go red. A check for missing keys that has never seen a missing key is not yet a check.

**S1 LANDED. What it turned out to be, beyond the plan above.**

- **It found a second live instance of the W4.7 bug on its first run.** The notification
  centre's "show older" button calls `t('common:loading')`, and `common:loading` has never
  existed, so a member paging through their notifications reads the literal word **"loading"**
  in all four languages. Added as a real key, worded to match `watch:audioLoading`, which was
  the only loading label in the app.
- **It is a script, not a jest test, and that was forced rather than chosen.** Half of it reads
  source files, and `apps/mobile/tsconfig.json` deliberately allows only `["jest"]` types.
  Adding `@types/node` to satisfy `node:fs` would put `process`, `Buffer` and the rest into
  scope for every app file, where they typecheck and then crash on a device. `scripts/*.mjs`
  is where this repo already keeps whole-repo static analysis, and `pr.yml`'s mobile job runs
  it in about a second, before the suite.
- **A third check emerged while writing it.** A template-built key
  (`` t(`academy:status.${s}`) ``) cannot be resolved, but its fixed prefix either names a real
  group of keys or names nothing, and the second is a typo worth catching. That converts 18 of
  the 53 unreachable call sites into checked ones and leaves 35 genuinely opaque, which is now
  a pinned tripwire rather than an unknown.
- **All six mutations verified**, including the two the plan did not list: a stray ordinal form
  given to German, and a new runtime-built key moving the tripwire.
- **The sixth mutation nearly recorded a false result.** The edit targeted
  `const { t } = useTranslation();` in a file that reads `const { t, i18n } = ...`, so the
  replacement was a no-op and the check passed. A mutation that silently fails to apply is
  indistinguishable from a check that catches nothing. Every mutation now asserts that it
  changed the file before drawing any conclusion from the result.

### S2 · The link follows the reader

- `privacyUrl(lang)` / `termsUrl(lang)` returning the locale-prefixed path, English unprefixed,
  matching the website's own routing. Closes the `links.ts` TODO.
- Every call site (onboarding welcome, settings, the new screen) passes the app's language.

**S2 LANDED, and it was smaller than the plan because the rule already had an owner.**

- **`localizedWebsiteUrl` already exists** (`src/lib/websiteUrl.ts`) and already knows how the
  website's locales are shaped: it was written for giving, promoted out of that feature when the
  Academy handoff needed it, and is covered by both suites. A third copy of "the site prefixes
  /de, /nl, /fr and leaves English at the root" would be a third thing to fix the day the site
  changes its routing, so the legal links call it rather than restating it.
- **A second defect surfaced next to the first.** `agbcglobal.com` 308-redirects to
  `www.agbcglobal.com`, and every other website link in the app (giving, Academy) already used
  `www`. Only the two legal constants did not. The redirect is what hid it: the bare host works,
  so nothing could ever fail on it. Now asserted, because a test is the only thing that can see
  a difference a redirect papers over.
- **Verified against the live site rather than against a 200.** All eight destinations return
  200, and each renders in its own language: `Privacy Policy`, `Datenschutzerklärung`,
  `Privacyverklaring`, `Politique de confidentialité`. A 200 alone would not have distinguished
  a correct page from the English one served under `/de`.
- Two mutations verified, each proving it changed the file first: dropping `www` reddens all
  five cases, and bypassing the localizer reddens exactly the two language cases and leaves the
  English, fallback and host cases green.

### S3 · PRIVACY

- Built from the frame first-hand, per the mockup-first rule. Route `/settings/privacy`.
- Settings' Privacy row navigates to it rather than opening a browser, restoring `04`.
- Its three exits: "Contact us about my data" to the contact route, "Read the full privacy
  policy" out to the locale-aware website, "Delete account" to `/settings/delete`.
- Four languages, both themes, four states where any apply.

### S4 · The legal copy pass

- `tagline` translated in DE/NL/FR.
- Consent, privacy-summary and deletion copy reviewed in all four languages (`22` §4).
- **The DELETE frame is stale and must be corrected**: it still reads
  `Credited to "A former member"`, which W4.5 removed from the app on the rule that copy never
  signals attrition. Left alone, a later session "fixes" the app back to the frame.

### S5 · Pseudo-localization

- A pseudo-locale generator (accent + expand + bracket) and a job that renders every screen
  under it to find clipping and concatenation.
- **Dispatch-only, no cron.** `nightly.yml` deliberately carries no schedule (CI budget: the
  minutes are a shared pool and an emulator run is not free), and its own comment names
  pseudo-localization at W4.6 as arriving that way.

### S6 · String freeze
