# W3.1 · Audio slice

Build blueprint for Phase 3's first item. Behavioral truth is `08`; the data is `02`
(§Storage buckets, §sermons); the dashboard side is `17` §4. This doc carries the decisions
taken with Ayo, the slice order, the contract each slice leaves for the next, and the gates.
**Delete once W3.1 lands.**

## Decisions taken with Ayo (2026-08-14)

1. **The bucket is PRIVATE; playback URLs are signed with a 24-hour TTL, minted on player
   open.** `02` left `sermon-audio` open ("public-read or modest-TTL signed"); Ayo's call,
   made knowing the trade: sermon audios are the church's own uploads (some will never be on
   YouTube at all), so a link copied out of the app's traffic goes dead within a day instead
   of becoming a permanent free door. 24 hours cannot expire mid-listen (a URL minted on open
   outlives any single session, background included), and reopening mints a fresh one, so
   background playback and resume are unaffected. Guests still listen: the SELECT policy that
   gates minting covers `anon` too. This is a fence against casual spread, not a vault:
   nothing short of DRM stops a determined listener from keeping audio they can play, and
   that is disproportionate for sermons. `02` and `08` are synced in the slice-1 PR.
2. **The dashboard upload lands NOW, in W3.1, not Dashboard Phase C.** `25` and `17`'s
   phasing note conflicted; Ayo picked W3.1 (the "listen while driving" promise has no
   supply line without it, and the media team's weekly upload task needs the tool before
   launch). `17`'s phasing note is amended in the same PR.
3. **`sermons.audio_url` is renamed to `audio_path`.** Same reasoning and same safety
   argument as `testimonies.image_url` → `image_path` (W2.3): a signed URL expires, so what
   belongs on the row is the object path; and the column has never held a value in any
   environment (no seed sets it, the sync's field policy never touches it, prod has no app
   schema yet), so a straight rename costs nothing now and a release cycle later.

## Slice order

**1a · The shelf (backend unit, this session).** Migration: the `sermon-audio` bucket row
(private, 150 MiB cap, `audio/mpeg` + `audio/mp4` + `audio/aac` + `audio/x-m4a`), storage
policies (below), the `audio_path` rename, and the dangling-reference guard. pgTAP `034`.
Local `[storage] file_size_limit` raised (50 MiB would refuse a normal sermon). Types
regenerated; the four mobile call sites follow the rename. Spec syncs per decisions 1-3.

**1b · The dashboard module (frame gate, then code).** Frames composed in
`design/mockups/dashboard.html` (house rule: no dashboard surface is built without an
approved frame; the four states are surfaces too) covering BOTH flows: attach audio to a
synced sermon, and create a manual audio-only sermon (`youtube_id` null; the schema and the
player's `audioOnlyPending` state have supported this since W1.3, and it is exactly the
"our own audios, not on YouTube" case Ayo raised). Then the module: `manage_sermon_audio`
as an admin-only `DashboardAction`, upload direct from the browser to Storage under the
admin's own JWT (a 60 MiB file must not ride through a server action; storage RLS is the
gate), then an attach server action that re-authorizes, **magic-byte checks the uploaded
object** (signed URL + `Range: bytes=0-11`, never the client's Content-Type), and writes
`audio_path` + metadata (`speaker`, `series`, `duration_sec`) to the row. Replace =
new object + delete old, write-once like `testimony-photos`; remove clears the column
BEFORE deleting the object (the guard forbids the other order). Vitest server tests against
the local stack + the IDOR/refusal matrix.

**2 · The native rebuild.** `expo-audio` + `["expo-audio", { enableBackgroundPlayback:
true }]` config plugin. NEW NATIVE MODULE: the dev clients on both physical devices cannot
load it until new EAS dev builds are made (Ayo's go-ahead required, house rule). Guard the
import (CopyRow pattern) so `SERMON` degrades on the old clients. Consider carrying
`expo-notifications`' native half on the same build so W3.3 does not force a second rebuild
(the W2.10 Sentry trick); decide with Ayo at that session.

**3 · The player.** The audio engine (`setAudioModeAsync` playsInSilentMode +
shouldPlayInBackground + doNotMix; `setActiveForLockScreen` with title/artist/artwork,
mandatory on Android), audio-only toggle (enabled only when `audio_path`, tooltip
otherwise), ±15s, speed 1x/1.25x/1.5x, interruption handling, and the server-synced resume
layer: throttled `playback_positions` writes (~10s, plus pause/exit/background) and
seek-on-open preferring the server position when signed in (within-30s-of-end = start over,
under 15s = not worth restoring, `08`). Signed URL minted on open, re-minted on a playback
error that smells like expiry. Play Console mediaPlayback declaration noted for release.

**4 · The member surfaces.** Save (gate + `saved_items`), MY-LIST, SERMON-NOTES (autosave),
all against existing W1.3 tables; four states each; mockup frames exist in
`entry-flow.html` (verify edge/guest variants have frames before building; a surface is a
state). Full matrix verification both themes.

## The storage contract (what 1a leaves behind)

- Bucket `sermon-audio`: private, `file_size_limit` 157286400 (150 MiB), mimes
  `audio/mpeg`, `audio/mp4`, `audio/aac`, `audio/x-m4a`.
- INSERT/DELETE: live-table admins only (`caller_is_admin_live()`), `aal2` sessions only
  (safe here where it was NOT safe on content tables: no mobile member ever writes this
  bucket, so the claim check locks nobody out), object names forced to `<uuid>.<ext>`
  (random ids per `02`, no path traversal, no PII in names). No UPDATE policy: objects are
  write-once, replacement is a new object.
- SELECT: `anon` + `authenticated`, the whole bucket. This IS the mint permission for the
  24h signed URLs, guests included. No status gating by design: `08`'s rot handling keeps
  audio playable when the YouTube half of a sermon vanishes.
- `sermons.audio_path` may only reference an object that exists in the bucket (trigger
  guard, service-role writes exempt like every guard in this repo). Clear the column first
  when removing audio.

## Gates and loose ends

- **Frame gate before 1b's UI** (see 1b). Composed frames rendered in Chrome, both themes,
  before approval (the HTML looks right while the render is wrong).
- **EAS rebuild gate before 3** (see 2).
- **Prod's global storage file-size limit** is a dashboard setting and stays at its default
  until the `19` cutover; raising it (needs the Pro plan, P6) joins the cutover checklist.
  Local is raised in `config.toml` in this PR.
- **Dev seed audio:** decide at 1b whether to preload a tiny MP3 into local storage via
  `config.toml` `objects_path` so `pnpm db:reset` leaves the player playable on device
  (the memory rule: every surface populated for device testing).
- **No analytics events land here**: the deferred ones belong to W3.3 and Phase 4;
  `sermon_played` already fires. Slice 3 should check whether its properties distinguish
  video from audio playback and extend at the call site if `22` §5 asks for it.
