# W2.1 · Auth BE + OTP screens: execution plan

Build blueprint for the first Phase 2 work item (multi-session). Behavioral truth is
`03-AUTHENTICATION.md`; this doc adds sequencing, the resolved decisions, the current
code state, and the implementation nuances found while planning (2026-07-25). Delete
once W2.1 lands. Read `03` + `02` (profile gates) + `24` §1 rows 11-12 first-hand in
the build session; read `~/.claude/standards/security.md`, `backend.md`, `mobile.md`
before starting.

## What is already done (do not rebuild)

- **The DB gate (W0.10).** `profiles` already has `display_name`, `avatar_url`,
  `language (en/de/nl/fr)`, `onboarded_at`, `age_confirmed_at`, plus the trigger
  "`onboarded_at` is set once by AUTH-3" and write policies that require
  `onboarded_at IS NOT NULL` (`02`/`03`). pgTAP already asserts a half-onboarded and
  a deleted profile cannot write (`009`). So W2.1 wires the flow to an enforced gate;
  it does not invent one. Confirm the `profiles` self-UPDATE policy lets a user set
  their own AUTH-3 fields once.
- **`/auth` is a stub** (`app/auth/index.tsx`) routing gated actions here; W2.1
  replaces it with AUTH-1..4.
- **`GateSheet` primitive exists** and several screens open it, routing to `/auth`.
  The full pending-action **gate-return replay is W2.2, NOT W2.1**. W2.1's AUTH-4
  returns to the prior screen / Home; W2.2 wires the remember-and-replay.

   already SPF/DKIM-verified; the remaining work is a scoped Resend SMTP credential for
   Supabase Auth + confirming DMARC is at enforcement. The daily loop never waits on it.
2. **Native module / EAS rebuild.** W2.1 adds `expo-secure-store` (for LargeSecureStore).
   Build the code first, verify on emulator/simulator, then ONE batched EAS dev build

   go-ahead. On-device auth verification happens after that rebuild.
3. **PR structure.** Two PRs: **BE slice first** (`feat/w2-1-auth-be`), then **screens**
   (`feat/w2-1-auth-screens`).

## Slice 1: Auth BE (`feat/w2-1-auth-be`)

Backend due-process (`25` §3): config + migration (if any) + hook contract + deno tests
+ types + green.

- **Supabase auth config** (`supabase/config.toml [auth]` / `[auth.email]`): OTP on,
  **magic link OFF** (code only, `{{ .Token }}`), `otp_length = 6`, `otp_expiry` ~600s.
  Review the `[auth.rate_limit]` block against `03` (per email + device + IP, attempt
  lockout, expiry) and `security.md` (throttle + progressive delay, NO attacker-triggerable
  hard lockout / account-DoS; uniform response, no enumeration). Verify config keys
  against **current Supabase docs**, not memory.
- **Localized OTP email templates (EN/DE/NL/FR)**: church-branded, plain HTML, the
  6-digit code large in the body AND the subject line. NUANCE: Supabase's built-in
  templates are **single-language per project**. To localize per user (`03`), implement
  a **Send Email Hook** (edge function) that renders the template in the recipient's
  language. Contract in `packages/shared`; `deno test` the render for all four locales.
  (Confirm the current Send-Email-Hook shape against live Supabase docs.)
- **LargeSecureStore session adapter** (`03` Sessions): wire the Supabase client's
  `auth.storage` to LargeSecureStore per Supabase's Expo guide (AES-256 key in
  `expo-secure-store`, AES-encrypted session in AsyncStorage; a session object exceeds
  SecureStore's 2 KB per-value limit). New deps: `expo-secure-store` (NATIVE → the
  rebuild), plus the crypto the guide uses (`aes-js` + `react-native-get-random-values`,
  or `expo-crypto`). Confirm deps at add time.
- **Review store-review bypass** (`03` §Security): the one allowlisted review email +
  a long random fixed code, checked server-side, `role='member'`, per-environment flag
  (**on dev/preview, off prod** except the submission window). Build on whatever
  Supabase's **current** test-OTP mechanism is (config test-OTP vs. short-circuit in the
  Send Email Hook): verify against live docs. The "born-pending + excluded from
  moderation" half is enforced by the moderation policy in W2.7, not here.
- **Tests:** pgTAP for any new/changed policy; `deno test` for the email hook (4-locale
  render + review-bypass); existing `003`/`009` profile-gate suites stay green; regen
  `database.types.ts` if the schema changes.

Resend SMTP secret is a preview/prod config step (Ayo provides the scoped credential);
dev stays on Mailpit, so the BE build never waits.

## Slice 2: Auth screens (`feat/w2-1-auth-screens`)

Mobile due-process (`25` §4): mockup-first (read the AUTH frames in
`design/mockups/entry-flow.html`), tokens + i18n keys only, four states, tests in-PR.

- **AUTH-1**: email entry (email keyboard, OS autofill), "why" copy, **Send code** /
  **Not now**; zod email validation.
- **AUTH-2**: 6-digit input (`one-time-code` autofill), 30s resend timer, masked
  sent-to (`a•••@gmail.com`), spam-folder hint after ~20s, **Change email**, and every
  error state: invalid / expired / too-many-attempts / **total OTP outage** / offline.
- **AUTH-3** (first sign-in only): display name, home branch (prefilled from the
  onboarding branch store), language (prefilled), **16+ declaration**, optional avatar
  (defer the real upload to W2.3/W2.9's private-bucket path; allow skip). One update sets
  `onboarded_at` + `age_confirmed_at` (+ name/branch/language); the trigger enforces
  one-time.
- **AUTH-4**: success → return to the prior screen / Home. (Gate-return replay = W2.2.)
- **Routing / session:** `onAuthStateChange` drives an auth store (guest vs member); a
  session with `onboarded_at IS NULL` routes to AUTH-3 on launch; killed-mid-AUTH-3
  resumes there. Refresh-failure → guest transition + the "signed out" banner (`03`).
- **i18n:** an `auth` namespace (EN complete; DE/NL/FR keys exist per convention).
- **Tests:** RNTL for each screen's states + the OTP flow + half-created routing; unit
  tests for the auth store / gate-state logic.
