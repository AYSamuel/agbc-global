## What the pre-build survey found

### 1. The deep links verify against nothing, and the fix is smaller than it looks

Neither association file exists. `https://www.agbcglobal.com/.well-known/assetlinks.json` is a
404, and the apex host answers **308** to everything, including `/.well-known/`.

`app.config.js` declares **both** hosts, and that is the trap. On **Android 11 and lower** the
system "establishes your app as the default handler for the specified URL patterns only if it
finds a matching Digital Asset Links file for ALL hosts in the manifest"
([verify-android-applinks](https://developer.android.com/training/app-links/verify-android-applinks)).
The app's floor is **Android 7** (Expo SDK 57), so most of the supported range is in that rule.
Declaring an apex that can only ever answer with a redirect therefore risks taking `www` down
with it, and it fails exactly the way `19` warns the wrong fingerprint fails: links keep opening
in the browser with no error anywhere.

So: **declare `www` only**, serve the file there, and record that every link the app or the
church generates uses `www`, which is already the rule W4.6 set for the legal links. Changing
Vercel's apex redirect was the alternative and was rejected: it is domain-level configuration on
a live church website, and the app's manifest is the smaller, reversible surface.

Nothing generates an `https://…/app/…` link yet (the website has no `/app` route and the app's
own deep links use the `agbcglobal://` scheme), so this is machinery being made honest rather
than a broken feature.

The Android fingerprint is already known: the **Play App Signing** SHA-256 in `19`, never the
upload key. The iOS file additionally needs the **Apple Team ID**, which only App Store Connect
has, so `apple-app-site-association` is prepared and NOT served until that value exists: a file
with a placeholder `appID` is worse than no file, because Apple caches it.

`Desktop/agbc`'s `src/lib/legal.ts` holds the blanks that keep the Impressum incomplete under
§ 5 DDG and the draft banner on all three legal pages. Its own rule is "never guess a value.
Anything not confirmed by a Companies House record stays an empty string", and Companies House
is a public register, so three of them were looked up rather than waited for
([SC812955](https://find-and-update.company-information.service.gov.uk/company/SC812955)):

| Fact | Value from the register |
|---|---|
| Company number | **SC812955** |
| Registered office | **156 Highcoats, Coatbridge, Scotland, ML5 3PF** |
| Directors | **Rev Olayinka Ademiluka**; **Dr Esther Fiyinfoluwa Babatunde** (both active, appointed 7 June 2024) |

The register also **corroborates every fact the file already asserted**: the exact name, private
company limited by guarantee without share capital, registered in Scotland, SIC 94910 activities
of religious organisations. Incorporated 7 June 2024, status active.

**Two remain and neither is on any register:** whether the company is VAT registered, and the
solicitor sign-off that flips `reviewed`. Those are Ayo's.

### 3. The review bypass is built, and the submission has to switch it on

`supabase/functions/review-signin` exists with its tests. `03` requires it **disabled in
production except from submission until approval + 7 days**, with a fresh code per window. That
is an operational sequence with a deadline attached, so it belongs in a runbook rather than in
somebody's memory.
